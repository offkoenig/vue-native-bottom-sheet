# vue-native-bottom-sheet

Production-ready выезжающая снизу панель (bottom sheet) для Vue 3 с физикой, максимально приближённой к нативным шторкам iOS/Android: инерция по скорости свайпа, resistance-эффект «резинки», пружинные (spring) анимации вместо CSS-таймингов, snap-points и полный набор a11y-механик.

Работает как обычная библиотека компонентов в **любом** Vue 3 (≥3.4) проекте — Vite, webpack/vue-loader — и как полноценный **Nuxt 3 модуль** с авто-регистрацией. Не требует Tailwind: все стили самодостаточны (scoped CSS + CSS-переменные для темизации).

## Возможности

- **v-model** через `defineModel()`.
- 3 именованных слота — `header`, default, `footer` — со scoped-пропом `close()`.
- Рендер через `<Teleport to="body">`, полностью SSR-safe.
- Во время драга меняется **только** `transform: translate3d(...)` — стабильные 60 FPS.
- Velocity-based инерция: быстрый свайп вниз закрывает шторку, даже если протянуто всего ~10% высоты.
- Rubber-band при перетягивании выше самой открытой точки — формула из WebKit/UIScrollView.
- Настраиваемые snap-points — фиксированные проценты или `'content'` (авто-подгонка и живая адаптация под реальную высоту контента), все settle/open/close-анимации — пружина (закон Гука), а не CSS-transition.
- Scroll lock body с учётом iOS Safari, плавная передача жеста скролл → драг.
- Escape закрывает, Tab держит фокус внутри панели, уважает `prefers-reduced-motion`.
- Тёмная тема из коробки — по `prefers-color-scheme` и/или классу `.dark` на предке.
- Не требует Tailwind/UnoCSS — стили едут внутри компонента; при желании поверх можно добавлять свои классы через `panelClass` / `contentClass` / `backdropClass`.

## Установка

```bash
npm install vue-native-bottom-sheet
```

Единственный peer-зависимый пакет — `vue` (^3.4.0). `@nuxt/kit` нужен только если вы используете Nuxt-модуль (см. ниже) — для обычного Vue-проекта он не требуется и не устанавливается.

## Использование в обычном Vue 3 (Vite и т.д.)

Компонент можно импортировать напрямую:

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { BottomSheet } from 'vue-native-bottom-sheet'

const isOpen = ref(false)
</script>

<template>
  <button @click="isOpen = true">Открыть</button>

  <BottomSheet v-model="isOpen" :snap-points="[50, 100]">
    <template #header="{ close }">
      <h2>Заголовок</h2>
      <button @click="close">✕</button>
    </template>

    <p>Контент</p>

    <template #footer="{ close }">
      <button @click="close">Готово</button>
    </template>
  </BottomSheet>
</template>
```

Либо зарегистрировать глобально через плагин — тогда компонент доступен в шаблонах без импорта:

```ts
// main.ts
import { createApp } from 'vue'
import { BottomSheetPlugin } from 'vue-native-bottom-sheet'
import App from './App.vue'

createApp(App)
  .use(BottomSheetPlugin /* , { componentName: 'MySheet' } — опционально */)
  .mount('#app')
```

> Компонент поставляется как исходный `.vue`-файл (не пре-бандлится в JS) — его компилирует тот же `@vitejs/plugin-vue`/`vue-loader`, что уже есть в вашем проекте. Это стандартная и проверенная практика для Vue-библиотек: Vite штатно обрабатывает `.vue`-файлы независимо от того, лежат они в `src/` или в `node_modules/`, в том числе при препребандлинге зависимостей в dev-режиме.

## Использование в Nuxt 3

### Вариант A — модуль с авто-импортом (рекомендуется)

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['vue-native-bottom-sheet/nuxt'],

  // опционально:
  nativeBottomSheet: {
    componentName: 'BottomSheet', // под каким именем регистрировать
  },
})
```

После этого `<BottomSheet>` доступен в любом компоненте проекта без импорта — как встроенный компонент Nuxt. Стили подключать отдельно не нужно: они едут внутри `.vue`-файла и подхватываются штатной сборкой Nuxt.

### Вариант B — ручная регистрация

Если не хочется подключать модуль, компонент можно импортировать точно так же, как в обычном Vue:

```vue
<script setup lang="ts">
import { BottomSheet } from 'vue-native-bottom-sheet'
</script>
```

Оба варианта используют один и тот же компонент — модуль лишь избавляет от ручного импорта.

Внешний вид настраивается через CSS-переменные на классе `.vbs-panel` — переопределите их в глобальном CSS проекта:

```css
.vbs-panel {
  --vbs-bg: #0a0a0a;
  --vbs-fg: #f5f5f5;
  --vbs-radius: 1rem;
  --vbs-shadow: 0 -12px 32px -8px rgba(0, 0, 0, 0.4);
  --vbs-ring: rgba(255, 255, 255, 0.08);
  --vbs-handle-color: #52525b;
  --vbs-border-color: #27272a;
  --vbs-max-width: 32rem; /* ширина панели на экранах ≥640px */
}
```

Тёмная тема применяется автоматически по `prefers-color-scheme: dark`, а также — если в проекте принята конвенция Tailwind с классом `.dark` на `<html>`/предке — по этому классу, без необходимости иметь сам Tailwind.

Если этого недостаточно, `panelClass` / `contentClass` / `backdropClass` принимают любые классы (в том числе Tailwind/UnoCSS, если они есть в проекте) и накладываются поверх встроенных:

```vue
<BottomSheet v-model="isOpen" panel-class="ring-2 ring-blue-500">
```

## Пропсы

`v-model` (проп `modelValue: boolean`, событие `update:modelValue`) обязателен для управления открытостью — остальные пропы опциональны.

| Проп | Тип | По умолчанию | Описание |
|---|---|---|---|
| `snapPoints` | `(number \| 'content')[]` | `[50, 100]` | Точки прилипания в % высоты вьюпорта. `'content'` вместо процента измеряет реальную высоту header+default+footer через `ResizeObserver` (не выше 100dvh) и сама доезжает до новой высоты, если контент меняется, пока шторка открыта. Порядок не важен — сортируются автоматически, в т.ч. заново вокруг «плавающей» точки `'content'`. |
| `defaultSnapPoint` | `number` | `0` | Индекс в `snapPoints`, до которого шторка открывается по умолчанию. |
| `closeThreshold` | `number` | `0.5` | Порог скорости свайпа (px/мс), после которого срабатывает инерционный переход/закрытие. |
| `rubberBandResistance` | `number` | `0.55` | Сопротивление (0..1) эффекта «резинки» выше самой открытой точки. `0.55` — родная константа WebKit/UIScrollView. |
| `springStiffness` | `number` | `300` | Жёсткость пружины (`k`). Больше — быстрее и «туже». |
| `springDamping` | `number` | `32` | Демпфирование пружины (`c`). Больше — меньше «доезд» в конце. |
| `springMass` | `number` | `1` | Масса тела пружины (`m`). |
| `respectReducedMotion` | `boolean` | `true` | Уважать ли `prefers-reduced-motion: reduce` (мгновенные переходы вместо пружины). Если шторка открывается вообще без анимации и вы этого не ожидали — почти наверняка дело именно в этом: сначала проверьте настройку accessibility в ОС/браузере, прежде чем считать это багом. Отключайте осознанно (например, в демо, где сама анимация — предмет показа). |
| `showBackdrop` | `boolean` | `true` | Показывать затемнённый фон. |
| `backdropOpacity` | `number` | `0.45` | Максимальная непрозрачность backdrop (0..1) в полностью открытом состоянии. |
| `closeOnBackdropClick` | `boolean` | `true` | Закрывать по клику на backdrop. |
| `closeOnEscape` | `boolean` | `true` | Закрывать по клавише `Escape`. |
| `dismissible` | `boolean` | `true` | Если `false` — свайп/backdrop/`Escape` не закрывают шторку; закрыть можно только программно. |
| `lockBodyScroll` | `boolean` | `true` | Блокировать скролл `<body>`, пока шторка открыта. |
| `ariaLabel` | `string` | `'Panel'` | `aria-label` диалога. Для русскоязычного интерфейса переопределите, например, на `'Панель'`. |
| `zIndex` | `number` | `60` | Базовый z-index (backdrop = `zIndex`, сама панель = `zIndex + 1`). |
| `panelClass` | `string \| object \| array` | — | Доп. классы на корневой элемент панели. |
| `contentClass` | `string \| object \| array` | — | Доп. классы на скроллируемую область контента. |
| `backdropClass` | `string \| object \| array` | — | Доп. классы на backdrop. |

### Подгонка под высоту контента

Вместо процента «на глаз» точкой прилипания может быть буквально строка `'content'`:

```vue
<BottomSheet v-model="isOpen" :snap-points="['content']">
  <p>Ровно моей высоты, не больше.</p>
</BottomSheet>
```

Под капотом `header` + дефолтный слот + `footer` измеряются через `ResizeObserver` (не выше `100dvh`) и конвертируются в translateY точно так же, как и процентная точка — та же сортировка, тот же rubber-band, та же пружина. Если высота контента меняется, пока шторка открыта (раскрылся аккордеон, догрузилась картинка), она сама доезжает до новой высоты, не закрываясь.

`'content'` можно комбинировать с фиксированными процентами, например `:snap-points="['content', 100]"` — открывается по высоте контента, но быстрый свайп вверх всё ещё доводит до 100%. Пара с точкой, которую контент не может превысить (`100`), держит порядок сортировки стабильным; комбинация с *промежуточной* фиксированной точкой (например, `['content', 50]`) тоже поддерживается, но если измеренная высота контента когда-нибудь пересечёт эту точку — порядок точек (а значит и то, какому индексу соответствует какая позиция) поменяется соответственно.

## События (Emits)

| Событие | Payload | Когда вызывается |
|---|---|---|
| `update:modelValue` | `boolean` | Стандартное для `v-model`, эмитится при любом изменении открытости. |
| `opened` | — | Анимация открытия завершена. |
| `closed` | — | Анимация закрытия завершена, панель убрана из DOM. |
| `snap` | `(index: number, percent: number)` | Панель «прилипла» к одной из `snapPoints` (не к закрытому состоянию). |
| `drag-start` | — | Начался жест перетаскивания (после прохождения порога движения). |
| `drag-end` | `(velocity: number)` | Жест завершён. `velocity` в px/мс: `+` — движение вниз, `−` — вверх. |

## Слоты

| Слот | Scoped props | Описание |
|---|---|---|
| `header` | `{ close: () => void, snapIndex: number }` | Шапка: заголовок, кнопка закрытия и т.д. Визуальная «хваталка»-индикатор рендерится компонентом автоматически **над** этим слотом. |
| default (без имени) | `{ close: () => void }` | Основной скроллируемый контент. |
| `footer` | `{ close: () => void }` | Фиксированный подвал (кнопки подтверждения и т.п.). |

## Программное управление снаружи

Через `defineExpose` доступны `close()` и `snapToIndex(index)` — берутся через template ref:

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { BottomSheet } from 'vue-native-bottom-sheet'

const isOpen = ref(false)
const sheet = ref<InstanceType<typeof BottomSheet> | null>(null)

function expandFully() {
  sheet.value?.snapToIndex(1)
}
</script>

<template>
  <BottomSheet ref="sheet" v-model="isOpen" :snap-points="[35, 100]" />
</template>
```

## Математика физики свайпа

### 1. Система координат

Панель — элемент высотой `100dvh`, зафиксированный у нижнего края экрана (`position: fixed; bottom: 0`). Всё положение описывается одним числом — `translateY` (px):

- `translateY = 0` → видно 100% высоты вьюпорта.
- `translateY = viewportHeight` → панель полностью под нижним краем экрана («закрыто»).
- Snap-точка `p`% высоты вьюпорта соответствует `translateY = viewportHeight × (1 − p / 100)`.

Так как во время жеста меняется только `translateY` через `transform: translate3d(0, Ypx, 0)`, браузер не пересчитывает layout — только compositing, что и даёт стабильные 60 FPS.

### 2. Скорость свайпа (velocity)

Компонент хранит скользящее окно точек `{y, t}` за последние ~150 мс. При отпускании пальца скорость считается как:

```
velocity = (yпоследняя − yпервая) / (tпоследняя − tпервая)      [px/мс]
```

Окно в 150 мс, а не разница между последними двумя `pointermove`, потому что мгновенная разница слишком шумная (особенно на Android) — окно сглаживает шум, но остаётся достаточно коротким, чтобы отражать именно финальный «выпускающий» рывок, а не весь жест целиком.

### 3. Rubber band («резинка»)

Когда панель тянут выше самой открытой snap-точки, применяется формула, которой сам WebKit пользуется в `UIScrollView` для оверскролла:

```
f(x, d, c) = (x · d · c) / (d + c · x)
```

где `x` — величина «лишнего» перетягивания (px), `d` — высота вьюпорта, `c` — `rubberBandResistance` (по умолчанию `0.55`, родная константа Apple). Функция асимптотически стремится к `d / c`: сопротивление растёт вместе с тем, как далеко тянут, но жёсткого стопора никогда не возникает.

### 4. Пружина (spring physics)

После отпускания (а также при программном open/close) `translateY` не анимируется CSS-transition с фиксированной длительностью, а интегрируется как затухающий гармонический осциллятор (закон Гука + вязкое демпфирование) методом semi-implicit Euler, на каждом кадре:

```
displacement  = position − target
acceleration  = (−k · displacement − c · velocity) / m
velocity     += acceleration · dt
position     += velocity · dt
```

где `k` = `springStiffness`, `c` = `springDamping`, `m` = `springMass`. Анимация останавливается, когда `|velocity| < 6 px/с` и `|position − target| < 0.5px`.

> Внутри симуляции скорость хранится в **px/с** (а не px/мс, как измеренная скорость жеста) — при старте пружины `velocity` из жеста один раз умножается на 1000. Это перевод единиц для физически корректного интегрирования по `dt` в секундах.

Ключевая деталь: **начальная `velocity` в этом уравнении — это измеренная скорость свайпа**. Именно поэтому быстрый флик долетает до цели быстро и с едва заметным характерным доездом, а медленный релиз плавно подкатывается — без отдельного расчёта «длительности анимации по скорости». Форму движения создаёт не заранее нарисованная easing-кривая, а реальная начальная скорость, поданная в уравнение.

При `k = 300, c = 32, m = 1` система слегка недодемпфирована: критическое демпфирование — `2√(k·m) ≈ 34.6`, а `32` немного ниже этого порога. Отсюда едва уловимый «доезд» в конце — деталь, которая считывается как «нативно», а не как линейная/резкая остановка.

### 5. Принятие решения при отпускании (settle)

1. `velocity > closeThreshold` (быстрый флик вниз) → переход на snap-точку на индекс ниже; если уже на самой нижней — закрытие.
2. `velocity < −closeThreshold` (быстрый флик вверх) → переход на snap-точку на индекс выше.
3. Иначе (медленный релиз) → прилипание к ближайшей по расстоянию точке среди всех `snapPoints` и «закрыто».

Именно пункт 1 позволяет закрыть шторку быстрым свайпом вниз, даже если протянуто всего ~10% высоты. Если `dismissible === false`, закрытие в п. 1/3 заменяется возвратом к самой нижней (первой) snap-точке.

### 6. Scroll handoff

Область default-слота слушает `pointerdown` и переходит в состояние `pending`. Драг шторки стартует, только если одновременно: (а) `contentRef.scrollTop <= 0` — контент уже докручен до самого верха, и (б) первое движение пальца — вниз. Иначе жест целиком отдаётся нативному скроллу — это убирает «дёргания». Похожая, но более простая логика (порог движения в 4px вместо `scrollTop`) применяется к области `header`-слота, чтобы клики по кнопкам внутри него не перехватывались драгом.

## Доступность (a11y)

- `role="dialog"`, `aria-modal="true"`, настраиваемый через `ariaLabel`.
- Фокус переносится на панель при открытии и возвращается на элемент-триггер при закрытии.
- `Tab`/`Shift+Tab` не выходят за пределы панели, пока она открыта (focus trap).
- `Escape` закрывает (если `closeOnEscape`).
- `:inert="!isOpen"` — пока панель скрыта, она недоступна для фокуса и скринридеров.
- Уважается `prefers-reduced-motion: reduce` — анимации становятся мгновенными.
- Перетаскивание не стартует из-под интерактивных элементов (`button, a, input, textarea, select, [role="button"]`).

## Архитектура пакета

```
src/
├── BottomSheet.vue   — сам компонент; поставляется как исходник (не бандлится)
├── types.ts           — общие типы (Props/Emits/Exposed), импортируются и компонентом, и index.ts
├── index.ts            — точка входа для обычного Vue: компонент + плагин + реэкспорт типов
└── nuxt.ts              — Nuxt 3 модуль: auto-import через @nuxt/kit
```

`BottomSheet.vue` не зависит ни от Nuxt (`import.meta.client` заменён на универсальную проверку `typeof window !== 'undefined'`), ни от Tailwind (стили — самодостаточный `<style scoped>` с CSS-переменными) — поэтому один и тот же файл одинаково работает и как обычный Vue-компонент, и как Nuxt auto-import.

Файл не пре-компилируется в JS намеренно: он резолвится и компилируется тем же Vite/webpack-пайплайном, что уже есть у потребителя пакета — так же, как если бы он лежал прямо в `components/` проекта. `index.ts`/`nuxt.ts` (обычные `.ts`-модули без Vue-синтаксиса) собираются в JS отдельно.

## Возможные проблемы

**Открывается/закрывается мгновенно, без анимации.** Почти всегда это активная системная настройка `prefers-reduced-motion: reduce` — компонент намеренно её уважает (см. раздел про доступность выше), так что это ожидаемое поведение, а не баг. Как проверить: в DevTools Chrome/Edge откройте Command Menu (`Cmd/Ctrl+Shift+P`) → «Emulate CSS prefers-reduced-motion» → убедитесь, что не выставлено «reduce»; либо проверьте настройки accessibility в ОС (например, «Уменьшение движения» на macOS/iOS, «Reduce animations» в GNOME). Если вам нужно, чтобы шторка всегда анимировалась независимо от этой настройки (например, демо-страница, где сама анимация — предмет показа), передайте `:respect-reduced-motion="false"`.

## Сборка из исходников

```bash
npm install
npm run build     # typecheck → .d.ts (vue-tsc) → .js (tsup) → копирование BottomSheet.vue в dist/
```

`dist/` после сборки содержит:

```
dist/
├── BottomSheet.vue      (исходник, скопирован как есть)
├── BottomSheet.vue.d.ts  (точные типы пропсов/эмитов/слотов — сгенерированы vue-tsc)
├── index.js / index.cjs / index.d.ts
├── nuxt.js / nuxt.d.ts   (только ESM — Nuxt 3 сам по себе ESM-first,
│                          а резолвинг пути опирается на import.meta.url,
│                          который не работает в CJS)
└── types.d.ts
```

## Требования

- Vue ≥ 3.4 (нужен `defineModel()`).
- Для Nuxt-модуля — Nuxt 3 (использует `@nuxt/kit`, указан как опциональный peer dependency — устанавливать вручную не нужно, если вы уже внутри Nuxt-проекта).
- Любой бандлер с поддержкой `.vue`-файлов (Vite, webpack + vue-loader) — то есть фактически любой стандартный Vue 3 проект.
